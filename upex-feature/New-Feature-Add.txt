### 1. Python (`py`) 

Runs everywhere without a separate compilation step.

* **Linux & macOS:** `python3 app.py`
* **Windows:**  `py app.py`

---

### 2. C (`c`) 

Requires a compiler like GCC, Clang, or MSVC.

* **Linux:**
* Compile & run : `gcc app.c -o app && ./app`



* **macOS:**
* Compile & run: `clang app.c -o app && ./app` *(or `gcc` via Xcode Command Line Tools)*



* **Windows:**

* Compile (GCC/MinGW) : `gcc app.c -o app.exe `
after that finished,
then run: .\app.exe    # don't use && here . double command prompt one after other

Or,

* Compile (MSVC) : `cl app.c`
after that finished,
then run: .\app.exe    # don't use && here . double command prompt one after other

# priotize cl here
# as it has two option, it should be automatic, because if one fails , then only it will execute other one 
# if one succeed , it won't execute other one

---

### 3. C++ (`c++`) 

* **Linux:**
* Compile  & run: `g++ app.cpp -o app && ./app`



* **macOS:**
* Compile & run: `clang++ app.cpp -o app && ./app`


* **Windows:**

* Compile (GCC/MinGW) : `g++ app.c -o app.exe `
then run: .\app.exe    # don't use && here . double command prompt one after other

* Compile (MSVC) : `cl /EHsc app.c`
then run: .\app.exe    # don't use && here . double command prompt one after other

# priotize cl here
# as it has two option, it should be automatic, because if one fails , then only it will execute other one 
# if one succeed , it won't execute other one

---

### 4. C# (`c#`) — *Microsoft's Enterprise Elegance*

* **All Platforms (via .NET CLI):**

* **Windows , linux , macos (Classic C# Compiler):**
* Compile  & run: 
`dotnet run --file app.cs`
or 
`csc app.cs && .\app.exe`   # for linux it's elf , for mac it's macho

# priotize dotnet here
# as it has two option, it should be automatic, because if one fails , then only it will execute other one 
# if one succeed , it won't execute other one

---

### 5. JavaScript (`js`) 

* **Linux, Windows, macOS:** `node script.js`

---

### 6. Swift (`swift`) — *Mac OS Native* 🍏

* **macOS:**
* Run directly: `swift script.swift`
* Compile to binary: `swiftc script.swift -o script` && ./script`

* **even linux**
* Run directly: `swift script.swift`
* Compile to binary: `swiftc script.swift -o script` && ./script`

* **even windows**
* Run directly: `swift script.swift`
* Compile to binary: `swiftc script.swift -o script.exe && .\script.exe`



---

### 7. Bash (`bash`) — *Linux & Mac Scripting*

* **Linux & macOS:**

* `chmod +x script.sh && ./script.sh`

---

### 8. Batch (`bat`) — *Windows Native* 🪟

* **Windows:**

* PowerShell: `.\script.bat`



---

### 9. Executable (`exe`) — *Windows Native Binary* 🪟

* **Windows:**
* PowerShell: `.\app.exe`


---

### 10. ELF (`elf`) — *Linux Native Binary* 🐧

* **Linux:**
* Grant execution permission & run: `chmod +x app.elf && ./app.elf`


---

### 11. Mach-O (`macho`) — *macOS Native Binary* 🍏

* **macOS:**
* Grant execution permission & run: `chmod +x app.macho && ./app.macho`

## remember , for elf ( linux) , macho (macos) , sh ( both mac & linux ) 
##  sometime app.elf or app.macho and app.sh will not have extension .elf , .macho, .sh
## so then just chmod +x app && ./app  ( for linux and mac )
